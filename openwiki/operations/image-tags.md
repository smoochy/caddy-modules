# Image Tags & Publishing

## Tagging Strategy

Every successful build publishes **two tags** to GHCR (canonical):

| Tag | Pattern | Purpose |
|-----|---------|---------|
| `latest` | `ghcr.io/smoochy/caddy-cloudflare-modules:latest` | Always points to newest build |
| `caddy-<x.y.z>` | `ghcr.io/smoochy/caddy-cloudflare-modules:caddy-2.8.4` | Reproducible deployments pinned to Caddy version |

Both tags are **mirrored to Docker Hub** when `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` secrets are configured:
- `smoochy84/caddy-cloudflare-modules:latest`
- `smoochy84/caddy-cloudflare-modules:caddy-<x.y.z>`

## Tag Generation

Generated by `docker/metadata-action@v6` in the `meta` step:

```yaml
tags: |
  type=raw,value=latest
  type=raw,value=caddy-${{ steps.decide.outputs.caddy_tag }}
```

The `caddy_tag` comes from the `decide` step which extracts the version from the Caddy base image labels.

## OCI Image Labels (Traceability)

Each published image includes comprehensive OCI labels for **traceability and change detection**:

### Base Image Labels
| Label | Value | Source |
|-------|-------|--------|
| `org.opencontainers.image.base.name` | `caddy:latest` | Hardcoded in workflow |
| `org.opencontainers.image.base.tag` | `2.8.4` | From base image `org.opencontainers.image.version` label |
| `org.opencontainers.image.base.digest` | `sha256:abc123...` | `crane digest caddy:latest` |
| `org.opencontainers.image.base.version` | `2.8.4` | Same as base.tag |

### Addon Labels (Dynamic)
For each addon discovered from Dockerfile `--with` lines (index `N`):

| Label | Example Value |
|-------|---------------|
| `org.opencontainers.image.addon.N.name` | `github.com/caddy-dns/cloudflare` |
| `org.opencontainers.image.addon.N.version` | `v1.2.3` |

Generated dynamically in `addon_labels` step - **no hardcoded addon count**.

### Legacy Label (Backward Compatibility)
| Label | Value |
|-------|-------|
| `org.opencontainers.image.cloudflare.version` | Cloudflare DNS module version |

Kept for compatibility with existing tooling that may read this specific label.

### Standard Labels
| Label | Value |
|-------|-------|
| `org.opencontainers.image.title` | "Caddy with additional modules" |
| `org.opencontainers.image.description` | "Caddy web server image with several additional modules baked in" |
| `org.opencontainers.image.url` | `https://caddyserver.com` |
| `org.opencontainers.image.documentation` | `https://caddyserver.com/docs` |
| `org.opencontainers.image.licenses` | `MIT` |
| `org.opencontainers.image.source` | `https://github.com/smoochy/caddy-modules` |

## Image Verification

### Check Published Labels
```bash
crane config ghcr.io/smoochy/caddy-cloudflare-modules:latest | jq '.config.Labels'
```

### Verify Multi-Arch Manifest
```bash
crane manifest ghcr.io/smoochy/caddy-cloudflare-modules:latest
```

### Pull Specific Version
```bash
# By version tag
docker pull ghcr.io/smoochy/caddy-cloudflare-modules:caddy-2.8.4

# By digest (fully reproducible)
docker pull ghcr.io/smoochy/caddy-cloudflare-modules:caddy-2.8.4@sha256:<digest>
```

## Reproducible Deployments

For production, **pin both tag and digest**:

```yaml
# docker-compose.yml
services:
  caddy:
    image: ghcr.io/smoochy/caddy-cloudflare-modules:caddy-2.8.4@sha256:abc123...
```

The digest is visible in:
- GitHub Actions Job Summary (build run)
- GHCR package page: https://github.com/smoochy/caddy-modules/pkgs/container/caddy-cloudflare-modules
- `crane digest ghcr.io/smoochy/caddy-cloudflare-modules:caddy-2.8.4`

## Docker Hub Mirror Details

| Condition | Result |
|-----------|--------|
| Secrets not configured | Skipped with summary notice |
| PR build | Skipped (validation only) |
| No build needed (`do_build=false`) | Skipped |
| Build + push successful | Both tags mirrored |
| Mirror fails | Summary shows failure, GHCR still published |

Mirror uses `crane copy` (no local pull/push) for efficiency.

## Adding a New Image Variant

When adding a variant (see [Architecture](/openwiki/architecture/overview.md#adding-a-new-image-variant)), replicate this tagging:
- `latest` → always newest
- `caddy-<x.y.z>` → matches Caddy base version
- Same OCI label structure (base + dynamic addon labels)
- Optional Docker Hub mirror under `smoochy84/caddy-<variant>`
