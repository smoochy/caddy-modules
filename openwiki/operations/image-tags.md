# Image Tags & Publishing

## Tagging Strategy

Every successful build publishes **two primary tags** to GHCR (canonical registry):

| Tag | Pattern | Purpose |
|-----|---------|---------|
| `latest` | `ghcr.io/smoochy/caddy-cloudflare-modules:latest` | Always points to newest build |
| `caddy-<x.y.z>` | `ghcr.io/smoochy/caddy-cloudflare-modules:caddy-2.8.4` | Reproducible deployments pinned to Caddy version |

When the Caddy version is a valid semver (not "latest"), an **additional alias tag** is also published:

| Tag | Pattern | Purpose |
|-----|---------|---------|
| `caddy-v<x.y.z>` | `ghcr.io/smoochy/caddy-cloudflare-modules:caddy-v2.8.4` | Alternative format for tooling that expects the `v` prefix |

Both primary tags are **mirrored to Docker Hub** when `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` secrets are configured:
- `smoochy84/caddy-cloudflare-modules:latest`
- `smoochy84/caddy-cloudflare-modules:caddy-<x.y.z>`
- `smoochy84/caddy-cloudflare-modules:caddy-v<x.y.z>` (when applicable)

## Tag Generation

Tags are generated by `docker/metadata-action@v6` in the `meta` step:

```yaml
tags: |
  type=raw,value=latest
  type=raw,value=caddy-${{ steps.decide.outputs.caddy_tag }}
  type=raw,value=caddy-v${{ steps.decide.outputs.caddy_tag }},enable=${{ steps.decide.outputs.caddy_tag != 'latest' }}
```

## OCI Image Labels (Traceability)

Each published image includes comprehensive OCI labels for **traceability and change detection**:

### Base Image Labels

| Label | Value | Source |
|-------|-------|--------|
| `org.opencontainers.image.base.name` | `caddy:latest` | Hardcoded in workflow |
| `org.opencontainers.image.base.tag` | `2.8.4` | From base image `org.opencontainers.image.version` label |
| `org.opencontainers.image.base.digest` | `sha256:abc123...` | `crane digest caddy:latest` |
| `org.opencontainers.image.base.version` | `2.8.4` | Same as base.tag |

These labels are injected at build time via the `labels` input of `docker/build-push-action`.

### Addon Labels (Dynamic)

For each addon discovered from Dockerfile `--with` lines (index `N` starting at 0):

| Label | Example Value |
|-------|---------------|
| `org.opencontainers.image.addon.N.name` | `github.com/caddy-dns/cloudflare` |
| `org.opencontainers.image.addon.N.version` | `v1.2.3` |

Generated dynamically in the `addon_labels` step - **no hardcoded addon count**. The workflow parses `Dockerfile-cloudflare` for all `--with` arguments and queries GitHub for each addon's latest release/tag.

### Legacy Label (Backward Compatibility)

| Label | Value |
|-------|-------|
| `org.opencontainers.image.cloudflare.version` | Cloudflare DNS module version |

Kept for compatibility with existing tooling that may read this specific label. Corresponds to the first addon (`addon_0_version`).

### Standard Labels

| Label | Value |
|-------|-------|
| `org.opencontainers.image.title` | "Caddy with additional modules" |
| `org.opencontainers.image.description` | "Caddy web server image with several additional modules baked in" |
| `org.opencontainers.image.url` | `https://caddyserver.com` |
| `org.opencontainers.image.documentation` | `https://caddyserver.com/docs` |
| `org.opencontainers.image.licenses` | `MIT` |
| `org.opencontainers.image.source` | `https://github.com/smoochy/caddy-modules` |

These are sourced from both the Dockerfile's `LABEL` instructions and the `metadata-action` output.

**Caption:** End-to-end publishing flow from tag generation through GHCR push to conditional Docker Hub mirroring.

### Build and Push Step

The `docker/build-push-action@v7` step:
- Builds for `linux/amd64,linux/arm64,linux/arm/v7` (single arch `linux/amd64` for PR validation)
- Pushes to GHCR on non-PR events
- Uses GHA cache for layer caching
- Injects all labels (metadata-action labels + base labels + addon labels + legacy label + custom description)

### Conditional Docker Hub Mirror

The mirror runs **only when all conditions are met**:
1. `do_build == 'true'` (a build actually occurred)
2. Not a pull request
3. `dockerhub_enabled == 'true'` (both `DOCKERHUB_USERNAME` and `DOCKERHUB_TOKEN` secrets are set)

The `dockerhub_mirror` step uses `crane copy` to copy each tag from GHCR to Docker Hub without pulling layers locally:

```bash
for tag in latest "caddy-${CADDY_TAG}"; do
  crane copy "${src_base}:${tag}" "${dst_base}:${tag}"
done

if [ "${CADDY_TAG}" != "latest" ]; then
  crane copy "${src_base}:caddy-v${CADDY_TAG}" "${dst_base}:caddy-v${CADDY_TAG}"
fi
```

## Validation Commands

### Check All Labels on Latest Image

```bash
crane config ghcr.io/smoochy/caddy-cloudflare-modules:latest | jq '.config.Labels'
```

### Check Specific Label Categories

```bash
# Base image labels
crane config ghcr.io/smoochy/caddy-cloudflare-modules:latest | \
  jq '.config.Labels | with_entries(select(.key | startswith("org.opencontainers.image.base")))'

# Addon labels
crane config ghcr.io/smoochy/caddy-cloudflare-modules:latest | \
  jq '.config.Labels | with_entries(select(.key | startswith("org.opencontainers.image.addon")))'

# Legacy label
crane config ghcr.io/smoochy/caddy-cloudflare-modules:latest | \
  jq '.config.Labels["org.opencontainers.image.cloudflare.version"]'
```

### Verify Manifest (Multi-arch)

```bash
crane manifest ghcr.io/smoochy/caddy-cloudflare-modules:latest | jq '.manifests[].platform'
```

### Verify Docker Hub Mirror

```bash
# Check tags exist on Docker Hub
crane ls smoochy84/caddy-cloudflare-modules

# Compare digests between registries
crane digest ghcr.io/smoochy/caddy-cloudflare-modules:latest
crane digest smoochy84/caddy-cloudflare-modules:latest
```

### Tag Assertion (CI Validation)

The workflow includes a `Assert produced tag set` step that validates the metadata-action output matches expected tags for the given Caddy version:

```bash
# Expected tags for semver (e.g., 2.8.4):
# - latest
# - caddy-2.8.4
# - caddy-v2.8.4

# Expected tags for "latest":
# - latest
# - caddy-latest
```
